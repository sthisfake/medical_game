# بازی آموزشی آناتومی صورت 🩺 (+ پنل مدیریت)

برنامهٔ **تمام‌پشته (full-stack) با Next.js (App Router)** و دیتابیس **SQLite (محلی) / PostgreSQL–Neon (ورکسل)** برای یک بازی آموزشی فارسی/راست‌به‌چپ:

- **بازی (صفحهٔ اصلی `/`):** تصویری از آناتومی نمایش داده می‌شود و دانشجو باید روی تصویر کلیک کند تا
  پاسخ را علامت بزند (مثلاً «عضلهٔ ماسِتر کدام است؟»). هر سؤال ۶۰ ثانیه زمان دارد و ۲ بار فرصت پاسخ.
- **پنل مدیریت (`/admin`):** مدیر (شما) مراحل و سؤال‌ها را می‌سازد، تصویر سؤال را آپلود می‌کند و
  **با کلیک روی خودِ تصویر، ناحیه‌های گزینهٔ پاسخ را رسم/ویرایش/حذف می‌کند و یکی را به‌عنوان
  «پاسخِ درست» علامت می‌زند** — بازی همان ناحیه‌ها را برای تشخیص پاسخ استفاده می‌کند.
  برای تشخیص پاسخ استفاده می‌کند.

## قوانین بازی

- ۴ مرحله (هر مرحله حدود ۱۰ سؤال). شرط عبور از هر مرحله: حداقل ۵۰٪ «درستِ تلاش اول».
- هر سؤال ۶۰ ثانیه؛ با اتمام وقت سؤال غلط حساب می‌شود و پاسخ درست + توضیح نمایش داده می‌شود.
- ۲ بار فرصت: درست در تلاش اول → امتیاز قبولی؛ درست در تلاش دوم → فقط نمایش؛ دو بار اشتباه →
  ناحیهٔ پاسخِ درست با رنگ سبز روی تصویر مشخص و توضیح آموزشی نمایش داده می‌شود.
- کلیک روی گزینه‌های نادرست = اشتباه (علامت ✕ قرمز روی نقطهٔ کلیک)؛ کلیک **خارج از همهٔ
  گزینه‌ها** تلاش مصرف نمی‌کند.
- **انواع سؤال:** تصویری (کلیک روی تصویر — چند ناحیهٔ درست ممکن است که باید همه کلیک شوند)،
  چهارگزینه‌ای (۳/۴ گزینه، ۱ درست)، ویدیویی (ویدیو + ۳/۴ گزینه، ۱ درست).
- شکست در یک مرحله → شروع دوباره از مرحلهٔ ۱.
- پایین صفحه شمارندهٔ زندهٔ درست/غلط نمایش داده می‌شود.
- **موبایل:** چیدمان برای گوشی تنظیم شده است — تصویر سؤال هم‌نسبت و محدود به ارتفاع صفحه
  (تا گزینه‌ها هم در دید بمانند)، دکمه‌های تمام‌عرض با ارتفاع لمس‌پذیر، نوار بالا و پایین
  جمع‌وجور، و پس از هر پاسخ بخش بازخورد نرم وارد دید می‌شود.

## اجرا

نیاز: **Node.js ۲۲** به بالا (برای دیتابیس داخلی `node:sqlite`).

```bash
npm install
npm run dev     # → http://localhost:3000
```

نسخهٔ نهایی:

```bash
npm run build
npm start
```

- صفحهٔ بازی: `http://localhost:3000/`
- پنل مدیریت: `http://localhost:3000/admin`

> بار اول که برنامه اجرا می‌شود، دیتابیس ساخته و یک **مرحلهٔ نمونه (۷ سؤال: ۵ تصویری — شامل یک
> سؤال چندپاسخهٔ دوطرفه — + ۱ چهارگزینه‌ای + ۱ ویدیویی)** به‌همراه ۳ اسکلت مرحله seed می‌شود تا
> بازی و مدیریت را امتحان کنید.
>
> **انتخاب خودکار دیتابیس:** اگر `DATABASE_URL` تنظیم نشده باشد، برنامهٔ محلی از
> SQLite (`data/game.db`) استفاده می‌کند (بدون نیاز به هیچ تنظیمی). اگر تنظیم شده باشد از
> PostgreSQL استفاده می‌شود — برای استقرار روی Vercel حتماً باید تنظیم شود (بخش زیر).

## پنل مدیریت — طرز کار

1. **`/admin`** → مراحل را بسازید/ویرایش/حذف کنید (`عنوان`، `آیکون`، `ترتیب`، `نسبت قبولی`).
2. روی «سؤال‌ها»ی یک مرحله بروید → **«افزودن سؤال»**.
3. در ویرایشگر سؤال:
   - **«نوع سؤال»** را انتخاب کنید:
     - **تصویری — کلیک روی تصویر**: تصویر را آپلود کنید؛ در بخش «گزینه‌های پاسخ» با ابزارهای
       ○ بیضی / ⬠ چندضلعی، ناحیهٔ هر گزینه را رسم کنید و از فهرست پایین، گزینه‌های «پاسخ درست»
       را علامت بزنید. **اگر چند ناحیهٔ درست داشته باشید (مثل عضلهٔ دوطرفهٔ چپ و راست)، در بازی
       باید همهٔ آنها کلیک شوند.**
     - **چهارگزینه‌ای**: ۳ یا ۴ گزینهٔ متنی وارد کنید و با دایرهٔ کنار هر ردیف، یکی را «درست»
       انتخاب کنید. می‌توانید یک **تصویر نمایشی** (غیرقابل کلیک) هم بالای گزینه‌ها آپلود کنید.
     - **ویدیویی**: ویدیو + ۳ یا ۴ گزینه با یک پاسخ درست. دو راه برای تعیین ویدیو:
       - **از پوشهٔ پروژه**: ویدیوهای کوتاه را در `public/videos/` بگذارید (مثلاً
         `video1.mp4`) و از منوی کشوییِ «انتخاب از پوشهٔ پروژه» انتخاب کنید. این فایل‌ها همراه
         برنامه در git و روی Vercel هم استقرار می‌یابند.
       - **آدرس/لینک**: آدرس مستقیم `mp4/webm` یا لینک YouTube هم می‌توانید وارد کنید.
       ویدیو با پخش‌کنندهٔ کامل (پخش/مکث/جلو و عقب/صدا/تمام‌صفحه) نمایش داده می‌شود.
   - **فشرده‌سازی خودکار تصویر:** تصاویر بزرگ پیش از آپلود در مرورگر کوچک و فشرده می‌شوند
     (حداکثر بُعد ۱۶۰۰ پیکسل، تبدیل به WebP، حجم هدف زیر ۳.۶MB)؛ پس می‌توانید عکس‌های سنگین را
     مستقیم انتخاب کنید. GIF و SVG دست‌نخورده می‌مانند و حجم نهایی زیر فایل نمایش داده می‌شود.
   - «متن سؤال» و «توضیح آموزشی» را بنویسید و «ساخت/ذخیرهٔ سؤال» را بزنید.
4. در بازی، رفتار هر نوع سؤال:
   - تصویری: کلیک روی ناحیهٔ درست = درست؛ ناحیهٔ نادرست = اشتباه؛ خارج از همهٔ گزینه‌ها =
     بدون مصرف تلاش؛ با چند ناحیهٔ درست، پاسخِ درست تا یافتن همهٔ ناحیه‌ها نمایش داده نمی‌شود.
   - چهارگزینه‌ای/ویدیویی: انتخاب گزینهٔ درست = درست؛ گزینهٔ دیگر = اشتباه (۲ فرصت).

پس از ذخیره، همان سؤال بلافاصله در بازی (`/`) ظاهر می‌شود.

## استقرار روی Vercel با Neon (Postgres)

برنامهٔ محلی از SQLite استفاده می‌کند، ولی روی Vercel (فایل‌سیستم خواندنی/موقتی) به یک
دیتابیس خارجی نیاز داریم — **Neon** انتخاب شده است (Postgres سرورلس، سازگار با Vercel):

1. در [neon.tech](https://neon.tech) یک پروژه بسازید (پلن Free برای شروع کافی است).
2. از داشبورد Neon، رشتهٔ اتصال **Pooled connection** را کپی کنید (شبیه
   `postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require`).
3. پروژه را در Vercel ایمپورت کنید (فریم‌ورک Next.js خودکار تشخیص داده می‌شود).
4. در Vercel → Settings → Environment Variables، متغیرهای زیر را اضافه کنید:
   - `DATABASE_URL` = رشتهٔ Neon
   - (اختیاری) `ADMIN_USER` و `ADMIN_PASSWORD` = اعتبارنامهٔ پنل مدیریت
5. Deploy کنید. در اولین اجرا، جدول‌ها و دادهٔ نمونه خودکار ساخته می‌شوند
   (schema و seed با قفل advisory انجام می‌شود تا چند instance با هم رقابت نکنند).

### ورود به پنل مدیریت

- پنل `/admin` و همهٔ درخواست‌های **تغییردهندهٔ** API (`POST/PUT/PATCH/DELETE`) با
  **Basic Auth** محافظت می‌شوند؛ خواندنِ بازی (`GET /api/stages` و …) عمومی است.
- اعتبارنامهٔ پیش‌فرض: نام کاربری `admin` و گذرواژه `admin`.
  برای تغییر، در Vercel متغیرهای `ADMIN_USER` و `ADMIN_PASSWORD` را ست کنید
  (`src/middleware.ts`).

> برای تستِ محلی با Neon هم کافی است `DATABASE_URL` را در `.env.local` بگذارید؛
> برنامه به‌صورت خودکار همان کد PostgreSQL را استفاده می‌کند.
>
> تصاویر آپلودی هم در خودِ دیتابیس (ستون base64) ذخیره می‌شوند؛ در پلن Free نئون حدود
> ۵۱۲MB فضا دارید — برای تصاویر کم‌حجم آموزشی کاملاً کافی است.

### ماندگاری داده‌ها پس از استقرار — چگونه کار می‌کند؟

- **روی Vercel:** همهٔ ویرایش‌ها (مراحل، سؤال‌ها، تصاویر، ناحیهٔ پاسخ) مستقیماً در
  PostgreSQL–Neon ذخیره می‌شوند؛ یعنی در **همهٔ استقرارهای بعدی و حتی ری‌استارت‌ها باقی می‌مانند**.
  در بالای پنل مدیریت، نشانگر «منبع داده» نوع دیتابیسِ فعال را نشان می‌دهد.
- **ایمن‌سازی:** اگر روی Vercel `DATABASE_URL` تنظیم نشده باشد، برنامه به‌جای SQLiteِ
  ناپایدار، با پیام واضح خطا می‌دهد تا هیچ ویرایشی بی‌سروصدا از بین نرود.
- **ساخت محتوا به‌صورت محلی و انتقال به ابر:** محتوایی که با پنل محلی (SQLite) ساخته‌اید را
  می‌توانید یک‌بار به Neon منتقل کنید:

  ```bash
  npm run snapshot                        # ← خروجی از دیتابیس محلی → data/snapshot.json
  DATABASE_URL="postgresql://…" npm run push:remote          # ← انتقال به Neon
  DATABASE_URL="postgresql://…" npm run push:remote -- --force  # ← جایگزینی کامل دادهٔ مقصد
  ```

  پس از این انتقال، از پنلِ استقرارشده در Vercel ادامه دهید؛ همهٔ تغییرات بعدی همان‌جا
  (در Neon) ذخیره می‌شوند و دیگر نیازی به انتقال دوباره نیست.

## API (خلاصه)

| متد | مسیر | کار |
| --- | --- | --- |
| GET | `/api/stages` | فهرست مراحل + سؤال‌ها (با ناحیه‌ها) |
| POST | `/api/stages` | ساخت مرحله |
| GET/PUT/DELETE | `/api/stages/[id]` | مرحلهٔ مشخص |
| POST | `/api/questions` | ساخت سؤال |
| GET/PUT/DELETE | `/api/questions/[id]` | سؤال مشخص |
| POST | `/api/upload` | آپلود تصویر (multipart) → ذخیره در دیتابیس |
| GET | `/api/uploads/[id]` | سرو تصویر ذخیره‌شده (با کش طولانی) |

حذف مرحله/سؤال به‌صورت آبشاری، تصویرِ ذخیره‌شدهٔ مربوطه را هم از دیتابیس پاک می‌کند.

## نکات فنی

- بک‌اندها: محلی **SQLite** با ماژول داخلی Node (`node:sqlite`)، و برای Vercel
  **PostgreSQL** با درایور سرورلس `@neondatabase/serverless`؛ هر دو در `src/lib/db.ts`
  بر اساس وجود `DATABASE_URL` انتخاب می‌شوند.
- تصاویر به‌صورت base64 در جدول `uploads` ذخیره و از `/api/uploads/:id` سرو می‌شوند؛
  مسیر ذخیره‌شده در سؤال مثل `/api/uploads/12` است.
- ناحیه‌ها با **مختصات نرمال (۰..۱)** ذخیره می‌شوند؛ روی هر اندازهٔ عکس و صفحه دقیق منطبق می‌شوند.
- seed نمونه در صورت خالی‌بودن دیتابیس، یک‌بار و به‌صورت هم‌زمان‌ایمن انجام می‌شود
  (قفل فایل در SQLite محلی، قفل advisory در Postgres).
- تست: `node scripts/smoke.mjs` (باید سرور روشن باشد؛ برای پورت دیگر:
  `SMOKE_BASE=http://localhost:3001 node scripts/smoke.mjs`).
